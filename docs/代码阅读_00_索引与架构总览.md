## 2. 系统在做什么

一次「活动」= 一批用户 × 一个模板 × 一条或多条渠道。系统把这件事拆成三段异步流水线：

```text
业务方 / 运营台 ──HTTP（Session）──► API ──MySQL(main_tasks，含 trace_id)──►
                            │
                   Scheduler │ 圈人（Static/HTTP/Demo + Filter）→ 分片 → PushMessage
                            ▼
                   MQ（high / normal）
                            │
                     Pusher │ 偏好/退订终检 → 渲染 → 限流 → 去重 → 渠道 → push_records
                            │         ↘ 异常节点写 trace_events（成功靠流水下钻）
                            ▼
                   渠道厂商 ──回执──► POST /api/v1/callbacks/receipt
```

| 进程 | 入口 | 循环 | 关键依赖 |
|------|------|------|----------|
| API | `cmd/api` | Gin HTTP | MySQL、Redis、Limiter、Auth、Segments、Preferences、Traces |
| Scheduler | `cmd/scheduler` | `loopSplit` + N×`loopClaim` | MySQL、Redis、MQ 写、Audience、ExcludeResolver |
| Pusher | `cmd/pusher` | 每队列一个 Consumer | MQ 读、MySQL、Redis、Channel、PreferenceResolver、Tracer |

## 3. 分层与依赖方向

```text
cmd/ → internal/bootstrap（唯一装配点）
        ├── server / handler / auth
        ├── app/*（campaign · template · callback · segment · preference · trace · …）
        ├── scheduler / push
        ├── port（SPI + 仓储）
        ├── domain
        └── adapter/*（MySQL / Redis / MQ / audience / channel / webhook）
pkg/ · web/
```

1. **业务只依赖 `internal/port`**（少数装配例外见 bootstrap）。
2. **纯逻辑下沉到 `domain`**，便于单测。

## 4. 依赖装配：`bootstrap.NewInfra`

| 步骤 | 做什么 | 注意 |
|------|--------|------|
| 1 | `config.Load` → `applyDefaults` | YAML 缺项不报错 |
| 2 | `NewDB` + `AutoMigrate` | **三进程都会跑 DDL**（`GET_LOCK` 串行化） |
| 3 | Redis / MQ | RocketMQ 需 build tag |
| 4 | `RegisterDefaults` → `RegisterFromConfig` | 后注册覆盖 stub |
| 5 | 人群：**Static → HTTP → Demo** | 取第一个 `Supports` 命中；Static 仅 `biz_scene=static` |
| 6 | Filter：合规 → 黑名单 → 退订 → AB | 顺序即执行顺序 |
| 7 | Segment / Suppression / Preference | 静态成员 repo 注入 StaticProvider |
| 8 | Webhook、ChannelQuotaLimiter | Limiter 可关闭 |

## 6. 全局约定速查

| 约定 | 说明 |
|------|------|
| 响应体 | `{code,message,data}` |
| `X-Request-Id` | `req_*` 请求级 |
| `X-Trace-Id` / `trace_id` | `tr_*` 活动级全链路 |
| 鉴权 | Session Cookie；回执与 healthz/readyz 放行 |
| 创建幂等 | `main_tasks.biz_id` |
| 投递防重 | `push_records(main_task_id,user_id,channel)` |
| Sentinel 错误 | paused / 时窗 / 免打扰 / 限流 → 留 PEL、不进 DLQ |
